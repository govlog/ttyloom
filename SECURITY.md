# Security policy

[English](#english) · [Français](#français)

## English

### Report a vulnerability privately

Use [GitHub’s private vulnerability report form](https://github.com/govlog/ttyloom/security/advisories/new).
Do not disclose a vulnerability in a public issue or pull request. If you cannot
use that form, contact Christopher AMIAUD at
[christopher.amiaud@gmail.com](mailto:christopher.amiaud@gmail.com).

Include the affected version or commit, OS and terminal, steps to reproduce,
and potential impact. A small example with fictional data is best. Never send
real account tokens, session files or private conversations.

Use accounts and data you control when testing. If credentials have been
exposed, revoke the affected token or session through the service’s settings.

### Versions and fixes

Use the [latest stable release](https://github.com/govlog/ttyloom/releases/latest)
when checking whether an issue still occurs. Fixes target the current release
and `main`; older releases are not maintained as separate branches. Reports
about older versions are useful if they identify an affected current path.

Ordinary bugs and feature requests belong in
[Issues](https://github.com/govlog/ttyloom/issues). See the
[account setup guide](docs/authentication.md) for credential and session handling.

## Français

### Signaler une vulnérabilité en privé

Utilisez le [formulaire privé GitHub](https://github.com/govlog/ttyloom/security/advisories/new).
Ne publiez pas de vulnérabilité dans une issue ou une pull request publique.
Si le formulaire est inaccessible, contactez Christopher AMIAUD à
[christopher.amiaud@gmail.com](mailto:christopher.amiaud@gmail.com).

Indiquez la version ou le commit concerné, le système, le terminal, les étapes
de reproduction et l’impact possible. Préférez un petit exemple avec des
données fictives. N’envoyez jamais de vrai token, fichier de session ou
conversation privée.

Testez uniquement avec vos comptes et les données que vous contrôlez. Si des
identifiants ont été exposés, révoquez le token ou la session dans les réglages
du service concerné.

### Versions et corrections

Vérifiez si le problème existe dans la
[dernière version stable](https://github.com/govlog/ttyloom/releases/latest).
Les corrections ciblent la version courante et `main` ; les anciennes versions
ne sont pas maintenues dans des branches séparées. Un rapport sur une ancienne
version reste utile s’il identifie un chemin encore concerné.

Les bugs ordinaires et demandes de fonctionnalités vont dans les
[issues](https://github.com/govlog/ttyloom/issues). Le
[guide de connexion](docs/authentication.fr.md) décrit la gestion des identifiants
et des sessions.
