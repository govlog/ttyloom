# Security policy

## Report a vulnerability privately

Use [GitHub’s private vulnerability report form](https://github.com/govlog/ttyloom/security/advisories/new).
Do not disclose a vulnerability in a public issue or pull request. If you cannot
use that form, contact Christopher AMIAUD at
[christopher.amiaud@gmail.com](mailto:christopher.amiaud@gmail.com).

Include the affected version or commit, OS and terminal, steps to reproduce,
and potential impact. A small example with fictional data is best. Never send
real account tokens, session files or private conversations.

Use accounts and data you control when testing. If credentials have been
exposed, revoke the affected token or session through the service’s settings.

## Versions and fixes

Use the [latest stable release](https://github.com/govlog/ttyloom/releases/latest)
when checking whether an issue still occurs. Fixes target the current release
and `main`; older releases are not maintained as separate branches. Reports
about older versions are useful if they identify an affected current path.

Ordinary bugs and feature requests belong in
[Issues](https://github.com/govlog/ttyloom/issues). See the
[account setup guide](docs/authentication.md) for credential and session handling.
