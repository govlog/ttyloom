# Changelog

## Unreleased

### Added

- **Networks box**: `/networks`, and at the first start, lists each network and its state; a page per network adds one (Telegram: how to get an api_id, then the QR code; Discord: the QR code or a token_cmd; IRC: the form of `/irc add`); connect, disconnect, log out of the account and remove (IRC) from it. ttyloom now starts with no network configured.
- **Age colour in the window list**: in window mode, the number and the name of a chat window fade with the age of its last message, from the text colour (less than an hour) to the dim colour (a week or more), in four steps. The `terminal` theme, with no RGB colours, has two: the last 24 hours, then older. The unread counter, the mention pulse and the current line keep their colours.

### Changed

- **Networks are modules**: Telegram, Discord and IRC each bring their configuration, launch, commands and texts from their own package under `protocols/`; adding a network is a package and one line in `cmd/ttyloom/main.go` ([docs/modules.md](docs/modules.md)). Nothing changes in `config.toml`, except that a file the client rewrites (`/set`, F4 to F7) lists its sections in alphabetical order.
- **Texts that named Telegram on every network**: the `/whois` line of a renamed chat names its network ("title on discord: …"), and the separator of the new-message box says "from the network".
- **IRC commands with several IRC networks**: typed outside an IRC window, they answer "several irc networks: …".
- **`/help`**: `/telegram`, `/discord`, `/irc` and `/dcc` now come at the end of the "chats" section, after the commands of the client.
- **Discord guild sections** come from the group the Discord module gives each channel; at the first start after the update they appear once the channel list arrives from the server.

## v0.7-beta — 2026-09-23

### Added

- **Full-size Telegram photos**: the conversation keeps the 800 px size, but the full-screen preview (a click on the image, `v`, `/view`) and `o` / `/open` now take the largest size Telegram has (1280 or 2560 px), downloaded once into `download_dir` next to the inline file, with a `_full` suffix. Photos with nothing above 800 px change nothing. The local history cache moves to format 3 and is rebuilt from the network at the first start: the older scrollback comes back as you scroll up, the downloaded files are reused as they are.

### Security

- **IRC password no longer sent in clear**: on a connection without TLS, neither SASL PLAIN nor `NickServ IDENTIFY` sends the password any more, unless the new `[[irc]] password_without_tls = true` key is set; a warning line says so at connection. The NickServ fallback itself is now sent only when the server offers no SASL at all, and never again after a SASL failure (no more IDENTIFY on top of a rejected SASL attempt). The `/irc add` form refuses `TLS = no` together with a NickServ password.
- **New `[[irc]]` key `nickserv_password_cmd`**: runs a command (no shell, 30 s timeout) that prints the NickServ password, like the Discord `token_cmd`. It wins over `nickserv_password`, which still works; a failing command is a launch error of the network.
- **CTCP hygiene**: VERSION, PING, TIME and CLIENTINFO requests are answered only when sent directly to me, never from an ignored nick, and at most 3 in a burst then one every 2 seconds; USERINFO is no longer answered.
- **DCC SEND hardening**: the listener now binds only the announced address (`dcc_ip`, else the IRC socket's), not every interface. An incoming offer pointing to `0.0.0.0`, loopback (unless my own `dcc_ip` is loopback), multicast or link-local is refused with a warning line; the offer label shows the `ip:port` it points to (`passive` for a reverse offer).
- **Desktop notifications**: the body now escapes `&`, `<` and `>`, so markup from a remote sender shows as plain text instead of being interpreted.
- **Remote text sanitized once at ingestion**: chat titles, usernames, sender names, message bodies, media labels and link descriptions, member lists, WHO/WHOIS/MOTD lines, login prompts, typing notices, search hits and error texts are neutralised when they arrive and when the cache is read, so a terminal escape sequence never reaches the stored data, the cache file, the window log or the clipboard.
- **Masked links ask before opening**: a click on a link whose text is not its target (a masked link, or the label of a link preview) now asks "Open `<url>`?" first; a plain link still opens at once. `mailto:` links with a query or a fragment (`?subject=`, `?attach=`, `#...`) are no longer clickable and are no longer sent as OSC 8 links.

### Fixed

- **Reactions read on Telegram**: a reaction to one of my messages no longer stays "new" on the phone. It is marked read on the server when it arrives in the window shown while the terminal has the focus, or at the next visit of the window; the unread reactions the dialog list reports at start-up are read the same way.
- **IRC history survives a reconnect**: a nick already in use at login (ghost, quick restart, changed nick in `config.toml`) no longer wipes the network cache — history, sidebar entries and `/rename` aliases survive.
- **`/part` and leaving a chat keep the history file on disk**: `/part`, the sidebar menu "leave the room" and "delete the chat" close the window and drop the sidebar entry, but the history file stays; it plays again when the room or query is opened again. When a query partner changes nick, the private window stays open with its history and shows "X is now known as Y"; the new nick opens its own window at its next message.
- **`/clear` no longer shrinks the disk history**: on any network, the next write merges the window into the file instead of replacing it.
- **Account switch archives the old cache instead of deleting it**: on Telegram and Discord, logging in with another account moves the old cache directory aside as `<dir>.old-<timestamp>`.
- **Cache format bumps no longer discard history**: IRC histories survive a cache format change (Telegram and Discord still refetch, since the server keeps their history); a history file that cannot be read is kept as `<id>.gob.bak-<version>` next to the new one. At start, when a cache's chat list cannot be read, its history files are no longer deleted — kept on IRC, moved aside elsewhere.
- **DCC SEND completion**: a send is reported as sent only after the peer acknowledged the whole file; a peer that closes early or stays silent 2 minutes now gives an error on the line instead of a false success.
- **`/nick` sticks**: the underlying IRC library no longer reverts it to the configured nick at the next keepalive.
- **`/ignore` also hides service lines**: JOIN, PART, QUIT, NICK, TOPIC and MODE lines of an ignored mask are dropped too (the member list still follows them).
- **Outbound IRC pacing**: lines I type or paste (messages, commands, DCC offers) now go out at most 4 at once, then one per second, avoiding an "Excess Flood" disconnect on a burst.
- **`/msg` targeting**: it now sends only to an exact chat name or a unique name prefix; a word found only inside a chat name is refused with "unknown" instead of being guessed.
- **Late terminal answers stay out of the input line**: a slow-link reply such as the kitty graphics probe no longer appears as typed text.
- **Confirmation debounce**: a `y` typed less than 300 ms after a confirmation question cancels it instead of confirming it (for example `dy` typed over one of my selected messages).
- **`@` mention box**: it now inserts and sends a member's plain name, without the `★` admin mark or the `(me)` suffix, and also offers IRC operators and voiced users. Nick completion now lists room members in sorted order.
- **Control characters removed from login prompts**: the question of a login prompt (for example the Discord QR scanner name) is stripped before the input line is drawn.
- **`cleanParts` no longer races a second instance**: at start, TTYloom now removes only the `.part-*` download temp files untouched for more than an hour, so a second running instance keeps its downloads.
- **`Config.Save` keeps unknown keys**: saving the configuration (`/set`, `/theme`, F4 to F7) keeps the top-level keys of `config.toml` this version does not know (comments are still lost; a file with such keys is written back with its keys sorted). When `config.toml` no longer parses (for example after a hand edit while TTYloom runs), a save no longer overwrites it — the error line names the file.
- **Disconnected upload no longer waits forever**: an upload waiting for a free upload slot now ends with an error if its network disconnects, instead of waiting indefinitely.
- **Sidebar highlight**: a chat line no longer stays highlighted after its context menu is closed by a login prompt or an account change.
- **Tab completion for `/set multiline `**: it now offers `on`/`off` like every other on/off key (the completion list used to forget that key).
- **NAMES, WHOIS and MOTD answers capped**: at 10000 lines each.

### Changed

- **IRC `/part` semantics**: leaving a room or a query closes the window and the sidebar entry but is no longer a destructive "forget the history" action (see Fixed, above).
- **Performance**: with many windows open, read receipts, edits and reactions now update only the views of their own chat, using much less CPU; history pages (including the start-up sync) no longer force a redraw of every window; day separators are no longer rebuilt at every frame.
- **Dependencies**: gotd/td v0.162.0, go-runewidth v0.0.30, x/image v0.46.0, x/sys v0.48.0, x/term v0.46.0 and x/text v0.42.0 (the indirect modules moved along, x/crypto v0.56.0 among them); the license bundle under `licenses/` is regenerated to match.

## v0.6-beta — 2026-09-14

- **GIF playback**: `gifplay = "always" | "hover" | "off"` in the configuration, `/set gifplay` live. `hover` moves only the GIF of the message under the mouse, the others hold their frame; `off` shows the first frame alone. Changing it reloads nothing. The GIF box and the preview play whatever the setting.

- **`/irc delete <name>`**: removes the `[[irc]]` table from `config.toml`, stops the network, closes its windows and drops its chats from the sidebar; Tab completes it. The cache directory of the network stays on disk.

- **Cursor under a GIF**: an animated frame in kitty went out with the cursor hidden for the whole of its bytes, so the input cursor went out and back at every frame. The bytes now go first (`a=t`), the cursor hides for the placement alone.

- **Tab bar**: the tabs leave their own line and sit at the right of the status line, right-aligned on its last column; `all` becomes `[*]`. The current tab, in its own colour, now names the network of the window shown, so the `[net]` segment of the status line goes while the tabs are on (it comes back with the tabs off, or with a single network). A narrow line gives the room by dropping whole segments of its left part, from the end — the flash message first, then `[away: …]`, `[Act: …]`, `[img: …]` — so it never ends in the middle of one; the clock, the account and the window stay, and the tabs go only when they no longer fit alone. The message area gains the line the old bar took.

- **Screenshots and documentation**: the screenshots are regenerated with real frames of the Discord and Telegram GIF searches (`scripts/gifshots.go`), a new tab mode scene shows an IRC channel, a WHOIS answer, a hot counter and the away segment, and the SVG exporter now takes the cell widths from the renderer and a colour emoji font, so emoji keep their size and colours and the overlays stay aligned. The documentation is in English only: the French README, manuals and screenshots are gone, a Languages table in the README lists the interface languages, and the changelog is in English. The manual, the README and the built-in help were checked line by line against the code: `/join #room [key]`, the IRC `/whois` rule, `/away`, the tab scoping of *Ctrl+X* and *Alt+←/→*, the Tab completion sources, `/part` instead of the non-existent `/leave`, the `g` key, `disconnect` on `/telegram` and `/discord`, `irc:<name>` on `/net`, IRC in the account setup guide.

## v0.5-beta — 2026-09-13

- **Versioning**: the project stays in beta; versions 1.0.0, 1.1.0, 1.1.1 and 1.2.0 become 0.1-beta to 0.4-beta below, the v1.x GitHub releases are withdrawn and the next versions follow the `v0.N-beta` form.
- **Tabs per network**: *F9* turns on a `[all] [telegram(6)] [discord(5)] [irc:libera]` bar above the status bar and moves from one tab to the next (a click does too), in network name order; a network tab shows only its windows (*Ctrl+X*, *Alt+←/→*, sidebar, aggregate view, *[Act: …]*), window 0 included, *Alt+N*, */win N* and */N* reach everything and the tab follows, and coming back to a tab returns to the last window seen on that network; `tabs = false` in the configuration, `/set tabs off` removes the bar. Same filter as `/net` and *Shift+F2*, no effect with a single network.
- **Hot windows**: a private message or a pending mention colours the `(N)` counter of the window in the mention colour, in bold, pulsing one second out of two, in the status bar, on the network tab and in the sidebar; visiting the window puts it out.
- **IRC commands**: `/part`, `/cycle`, `/topic`, `/nick`, `/notice`, `/invite`, `/names`, `/mode` (`/mode #room +ntk key`), `/kick`, `/ban` and `/kickban` (`*!*@host` mask through USERHOST), `/who`, `/whowas`, `/whois <nick>` in a framed layout, `/motd` (and the MOTD in window 0 at connection), `/ctcp`, `/quote`, `/ignore` (persistent masks in the `ignores` key of the `[[irc]]` table); `/join #room key`. Available in an IRC context only: a window of the network, the IRC tab or a single IRC network; the answers arrive in the window they were typed in, server errors in window 0. Tab completion of nicks and rooms given as arguments, of CTCP names and of masks; a nick at the start of a message becomes `nick: `.
- **/away [message]**: away on the networks that allow it (IRC `AWAY`, Discord idle with a custom status, experimental; nothing on Telegram); every network from the `all` tab, the only network of the current tab otherwise; `/away` alone comes back; an `[away: …]` segment in the status bar, nothing is said in the rooms.
- **IRC**: third network, as many servers as wanted, with no bouncer and no helper program (`ergochat/irc-go`). One `[[irc]]` table per network in `config.toml`, key `irc:<name>` (`/net irc:libera`, a sidebar section under its name, superscript `ⁱ`). `/irc add` opens an overlay form (name, host, port, TLS, nick, user, real name, NickServ password; ← → on the host scroll through thirteen known networks, Libera.Chat, OFTC, EFnet, DALnet, Undernet, IRCnet, QuakeNet, Rizon, hackint, GameSurge, EsperNet, Snoonet, tilde.chat, with host, port and TLS), writes the table and connects; `/irc` gives the state, `/irc connect` and `/irc disconnect <name>` start and stop a network. SASL PLAIN when the server announces it, `NickServ IDENTIFY` otherwise. The rooms joined (`/join`) are remembered in the table and joined again at start-up, `/leave` removes them; the disk cache is the scrollback, the server has no history. mIRC bold/italic/underline codes kept on reception (colours removed) and emitted for the styles of the draft; `/me`, `/whois` (aggregated WHOIS), *F3* (NAMES), service lines for JOIN/PART/QUIT/NICK/KICK/TOPIC/MODE, notices in window 0. Edits, reactions, receipts and search hidden. A `#room` typed from an unlinked window goes to the IRC networks only; from a linked window, to its own network only (two IRC networks no longer join the same room).
- **DCC**: `/dcc send <nick> <path>` (and `/send` in an IRC private conversation) sends a file from client to client, `/dcc get [nick]` accepts the last offer received (or the download key on its line), `/dcc` lists offers and transfers. Reverse offers accepted; `dcc_ip` and `dcc_ports` in the table for a NAT. No resume and no DCC CHAT.
- **Networks**: `/telegram disconnect` and `/discord disconnect` cut the connection while keeping the session; `login` connects again without a QR code. A network back after an outage reads the recent page of its loaded windows again (the displayed window right away, the others at their next visit): the messages of the interval take their place in the window instead of being lost, or put at the top where nobody looks.
- **Message menu**: a right click on a message opens its context menu where the click happened, the quick reactions of the conversation on the first line (seven at most, clickable), then its actions, edit and delete last (delete in the error colour); the entry under the pointer is the current entry. The help line of the selection and of the hover disappears, as does the guessed quick-reaction emoji; `hover = menu` and `highlight` now come to the same thing (highlight of the message under the pointer).
- **Deleted message**: a click on the *(deleted)* mark reveals the content kept by the cache (text, media, reactions), the next click hides it again.
- **Ctrl+↑ / Ctrl+↓**: from an empty input, *Ctrl+↑* edits my last message, then walks up from one of my messages to the next, *Ctrl+↓* comes back down; past the most recent one, the edit is left and the input cleared. A draft is never replaced.
- **Custom Discord emojis**: a received `<:name:id>` is displayed as `:name:`; the picker (*Ctrl+T*, *r*) lists the emojis of the server first, searched by their name, inserted as `:name:` and sent with their identifier; in kitty, their image takes the cell of the grid, downloaded once for the session. As Discord accepts any emoji as a reaction, the reaction picker there is the whole table, with the search.
- **Mentions by identifier**: the `@` box also offers the members with no nickname; the choice inserts `@Name`, sending turns it into a mention by identifier (Telegram entity, Discord `<@id>`), the longest name first so that “Bob” leaves “@Bobby” alone.
- **Sidebar**: `sidebar_split` (the `⊟` of the header, or `/set`) cuts the window list in two sections, rooms then direct messages, each in the order of `sidebar_sort`; numbers aligned to the right, marker stuck to the name; a Discord `#general` no longer doubles its `#` (sidebar, input label, new conversation, search), and a marker typed in `/rename` is removed.
- **Idle**: the terminal only counts as away after 1.5 s without focus; a quicker round trip marks nothing as read and leaves the red line, the counters and the bell in place.
- **Completion**: the choice lists of a double *Tab* are removed from the window by *Esc*.
- **Display**: the cursor is hidden while a kitty image is written (no more erratic blinking on the input line); the trace of a panic caught in a network goes to `/debug`.

## v0.4-beta — 2026-09-10

- **Documentation**: READMEs, manuals and built-in help (`/help`) checked against the code; `wl-copy`/`xclip` tools of the image copy, Discord GIF provider (KLIPY, no longer Tenor), *Alt+Backspace*, scope of the input styles.
- **Viewer**: *c* copies the displayed image to the system clipboard (`wl-copy` under Wayland, `xclip` under X11), ready to paste in another application; a video is refused.
- **Input styles**: *Ctrl+B*, *Ctrl+I*, *Ctrl+U* toggle bold, italic and underline at the cursor, and can be combined (underline+italic); the input line shows the style, the status bar the open styles (`[bold+underline]`), *Backspace* on a toggle cancels it. Sent as markdown on Discord and as entities on Telegram, with a styled local echo; valid as well when editing a message (*e*) and for `/me`, where the markers used to go out as raw bytes. *Ctrl+U* no longer deletes to the start of the line (*Ctrl+K* and *Ctrl+W* remain); *Ctrl+I* needs the kitty keyboard protocol, elsewhere it is *Tab*.
- **Scrolling over images**: an image cut by the top or the bottom of the window shows its visible part (kitty cropping) instead of being moved up whole or left blank; scrolling advances line by line.
- **Back to the last message**: scrolled up in the history, a *↓ last message* pill at the bottom right of the messages brings you back to the end in one click; it disappears under an image placed at that spot.
- **Ctrl+L**: clears the current window like the `clear` of a terminal; the lines stay in the history and come back with *Page Up* or the wheel (`/clear` still deletes them).
- **Completion**: `/m `, `/q ` and `/j ` followed by Tab with no letter show a short list (20), then a larger list (100) at the second Tab, contacts online first; `/join` offers channels and groups only, `/query` private chats only, `/msg` everything. Commands cycle in alphabetical order (`/ne` → `/net` → `/new`); a unique prefix resolves without Tab. `/qu` is an explicit alias of `/query`.
- **Query mode**: `/q name` and `/j channel` fix the send target while keeping the current flow visible, in every window, the aggregated window 0 included. `/q` or `/j` alone closes the mode. The target survives incoming messages and window changes; a late resolution result does not reopen a closed mode. As in ircii, the message sent is also displayed in the current window as `[msg(name)] text`, between “Opening conversation with name” and “Closing conversation with name”, without entering its history; `/msg` does the same without opening the mode.
- **Discord GIFs**: the `static.klipy.com` CDN of the current results is accepted; the previews all stayed on “discord: media URL refused”. Searches now explicitly ask the Discord provider for MP4 clips.

- **Discord by QR code**: a `[discord]` section without `token_cmd` is enough; TTYloom displays the QR code of the remote authentication of the official client (`remote-auth-gateway`, local RSA key, token decrypted on the spot), the phone scans and confirms it, and the token goes to `~/.config/ttyloom/discord.token` (0600). The session is a device in its own right: a logout from the browser no longer kills it. `/discord logout` closes the session on the server side and deletes the file; `token_cmd` is still possible and takes priority, with no QR code.
- **Networks**: `/telegram` and `/discord` (`status`, `login`, `logout`). `/discord login` runs `token_cmd` (or the QR code) again and connects without a restart: a token renewed in the password manager is taken on the spot, where “*token_cmd: exit status 1*” used to leave Discord absent until the next start; the error now carries the first line of the stderr of the command (“cat: … No such file”). `/telegram logout` closes the session on the server side (it leaves *Settings → Devices*), and `/telegram login` goes through the QR code again. A network whose connection dies (revoked token, fatal error) stops on its own and is started again by `login`; the client starts even when the only configured network fails on its token.
- **Input**: *Tab* after `/send` completes the path of the file (`~`, relative paths, spaces; a directory gets its `/` and the next *Tab* continues inside it). Conversation names complete from the start of any word of the title (`/query cop` → `copains du foot`) and `@nick` is understood; `/query`, `/msg`, `/join` accept a piece taken from the title when it is the only one to contain it. When several names remain and nothing can be added, a second *Tab* lists them. Completion also after `/log` and `/telegram`, `/discord`.
- **Telegram**: archived conversations (the “Archived” folder) are listed with the others; they only appeared at the next message received.
- **Window 0**: with `timestamps`, the system lines of the status windows (window 0, aggregate view, log) carry the time they arrived.
- **Sidebar**: in window mode (*F2*), the activity counter *(N)* is red, like the unread badge of conversation mode.

## v0.2-beta — 2026-09-05

- **Distribution**: Linux amd64 and arm64 binaries without Hunspell, archives with licenses, matching source and SHA-256 checksums. `ttyloom --version` shows the version and the source commit. A tag creates a draft release in GitHub Actions.

- **TTYloom**: new name, module `github.com/govlog/ttyloom`, `cmd/ttyloom` command and new configuration paths. The adapters are in `protocols/tgc` and `protocols/dsc`, with a single `go.mod`.
- **Start-up**: Discord can work on its own. The errors of the token provider are reported when no other network is available.
- **Security and stability**: the GIF limit applied before decoding, restrictions on Discord media URLs and on FFmpeg protocols, a video decoding timeout, the Telegram session written by atomic replacement, cache and Hunspell lifetime fixes. History requests keep a copy of the chat and the event loop regularly hands control back to the keyboard.
- **Files**: two successive image pastes have distinct paths; downloads include the network and the conversation identifier. An automatic threshold of zero also disables media of unknown size.
- **Maps**: OpenStreetMap attribution in the flow, in the viewer and in the saved PNG; tile cache shared between nearby positions; no off-screen map prefetch.
- **Documentation**: English and French READMEs, the story of the name, kitty screenshots in two languages, guides to obtain the credentials, a manual in French of its own and dependency notices.

- **Memory**: the decoded frames (PNG) of all media are capped at 256 MB in total. A Discord GIF displayed in the flow weighs 12 to 15 MB of frames and stayed in memory as long as the window lived, in kitty as in half blocks: a GIF session went past 7 GB of RSS. Beyond the cap, the media displayed longest ago lose their frames (never the ones on screen) and are decoded again from their file as soon as their line comes back on screen; a message from the cache never downloaded also loads its media when it is displayed. Closing a window frees its frames in every image mode.
- **Windows**: `/set cycle_mode last_unread` changes *Ctrl+X*: the unread windows one after another in the order of their numbers, then back to the window left behind; with no unread, the classic cycle. `next` (default) keeps the original behaviour.
- **Display**: `/set timestamps_seconds on` puts the seconds in the timestamp of the messages (`15:04:05`).
- **Paste**: a bracketed paste (`ESC[200~`) cut in two by a slow link (SSH, terminal without the kitty keyboard protocol) is no longer replayed key by key after 30 ms of silence — every `\r` sent a message, and a line starting with `/` ran a command. The client waits for the end of the paste, and a paste never finished comes out as it is, as a paste.
- **Display**: the bidirectional control characters (U+202A-202E, U+2066-2069) are neutralised like the other sequences; a file name or a link can no longer be read backwards (`gpj.exe` displayed as `exe.jpg`).
- **Discord**: an attachment of an unknown type is saved as `.bin` as on Telegram, so never handed to `xdg-open`; a download is capped at 512 MB whatever the server sends; the state of the connection is built from start-up, and a conversation replayed from the cache can no longer bring the client down before Discord answers.
- **Editing a media**: when the sender replaces the photo of a message, the new one is displayed instead of the old one kept in memory.
- **Configuration**: an unknown key of `config.toml` (a typo, `imagess = "off"`) is reported in window 0 at start-up instead of being ignored silently.
- **Media**: the format of a downloaded file is recognised from its first bytes (PNG, GIF, WebP, MP4…) and no longer from the type announced by the network — the Tenor route of Discord announced `image/gif` for animated WebP, and every preview of the picker stayed on “gif: can't recognize format”. An animated WebP goes through `ffmpeg` like a video (the Go decoder only reads still WebP), and the Discord picker takes the MP4 clip first.
- **README**: a GitHub README in English with screenshots rendered off screen by the drawing code itself (`docs/screenshots/`), the manual in French moving to a file of its own.
- **Discord search**: */search* in a room or a private message goes through the search of Discord (the one of the official client), and the global search (*Ctrl+F* twice) now queries every network that can search — Discord server by server then in the ten most recent private messages, fifteen seconds at most — or only the one of the */net* filter (which *F2* rotates in window mode), and merges the answers from the most recent to the oldest once they have all arrived, instead of keeping the last one to come.
- **GIF picker** (*Ctrl+G*, */gif [search]*): a centred box with the trending GIFs then the results of the typing, in animated previews (kitty or half blocks, downloaded into the cache for the visible cells only); *Enter* or a click sends the GIF to the conversation like a file send. Telegram goes through the *@gif* bot (the GIF leaves “via @gif”), Discord through Tenor with the token of the account (the message sent is the address of the page, which Discord expands); a Tenor GIF received animates in the flow instead of staying a link.
- **Mouse**: a terminal wheel with a multiplier (Ghostty sends three per notch) counts as one notch — the conversation sidebar scrolls one line per notch and not ten, the zoom of the preview one step. A click on the label of a photo, a video, a GIF or a map opens the internal preview, never the desktop; in the preview, the left button held down moves the zoomed image, a click without movement always closes.
- **Speed**: the sidebar only formats the lines on screen (×7 with 500 conversations), rendering a window of 2000 messages costs four times less per frame and twice less cold (ASCII width without segmentation, day compared as integers, style runs built in one go, one index table per rune instead of one style per rune in the wrapping).
- **Files**: `aliases.toml`, `sidebar.toml`, the cache and the maps go through the same atomic write as `config.toml` (temporary file then rename); `spell.txt` is created as 0600; the avatars are stored per network (`avatars/<network>/<id>.jpg`).

- **Video decoding**: a decoding in flight is cancelled when nobody waits for it any more — `s`, the window closed, the preview closed again, the media freed, the image mode changed — and the `ffmpeg` feeding it stops with it, instead of running to the end for frames nothing will display.
- **History**: a jump to an old message (search result, quote) loads a page far from what the window already held; the seam between the two now carries a `*** … messages not loaded` line instead of gluing the two blocks end to end without a word. The marker disappears as soon as a page fills the gap.
- **`video = autoplay`**: a video is only decoded over its whole length when it is displayed, instead of at download time — a hidden window or a message left above the view no longer fill the memory with frames nobody is looking at. A clip that gives a single frame stays at rest.
- **Sending images and files**: the line is displayed in the conversation right away, like a text send, instead of waiting for the end of the transfer then the echo of the server — that was the latency reported on one's own messages. The placeholder carries the name and the size of the file; the send receipt and the echo replace it with the real media, whichever of the two arrives first, and a failure marks the line instead of writing in window 0 only. Sends have a queue of their own (two in parallel) instead of sharing the one of the downloads, so a send no longer queues behind three downloads. Sending from a `/search` result or from the aggregate view: the status bar says which window the line went to.
- **Context menu**: the `leave the room` and `report / block` entries disappear when the network cannot do them (Discord) instead of asking for a confirmation with no effect; `close the chat` stays there, it only closes the window.
- **Discord**: the system messages (arrival in a room, pin, boost) are displayed as a `*** …` line instead of an empty line attributed to their author.
- **Discord**: the presence of the correspondents is given as soon as the conversation list is loaded, without waiting for a gateway update — a correspondent already *online* at start-up is reported right away.
- **Pointer tracking**: the hovered area takes the wheel and shows it — the `│` bar of the sidebar or the column of the scrollbar in the accent colour, the cursor of the scrollbar as a full block under the pointer. Above the sidebar, the wheel moves to the previous or next window in the order of the sidebar instead of scrolling the list, without ever opening a new one (a click is still needed), section headers and conversations never opened stepped over, with no overflow at the ends. `hover = off` gives the previous behaviour, to the byte.
- **Windows**: `/N` goes to window N (`/5`, `/21`), the **ircii** shortcut for `/window N`; a number outside the list answers with a single system line.
- **`/set lang`**: the texts already stored in memory also move to the new language — presence of the correspondents and the `cache` marker under the history, the latter otherwise staying stuck in the window (it is found by its text). Still waiting for the next event: the “seen <date>” presence, whose argument is translated too.
- **Log**: the file of `/log` is now called `<title>-<network>-<id>.log`, title cut at 40 characters — two conversations with long, close titles wrote in the same file. Existing logs keep their name (no migration).
- **Sidebar**: the header of window mode shows `[sort:…]` and answers a click like the one of conversation mode — the sort already held for both modes.
- **Sidebar**: window mode follows the F7 sort order (`recent`, `alpha`, `unread`) applied to the conversation of each window — window 0 first, windows without a conversation at the end in the order of their numbers. The numbers displayed stay the real window numbers, so with the default sort (`recent`) the lines are no longer in the order of their numbers.
- **Sidebar**: foldable sections — one `─── name ───` header per network and per Discord server, a click or `/fold` to fold, unread and windows aggregated on the folded header, state kept in `sidebar.toml`. Guild rooms listed without the `Guild /` prefix. No header with a single network without a guild.
- **Spell checking** (`/set spell fr|us|fr+us|off`): mistakes underlined in red in the input (undercurl when the terminal can), hunspell dictionaries of the system, personal dictionary `spell.txt`. `Ctrl+R` walks the mistakes (Enter corrects, `i` ignores, `a` adds, Ctrl+R skips, Esc quits); right click on an underlined word to correct that one alone. `/set spell_quotes on` also checks the `>` quotes and the code blocks. Build: `libhunspell-dev` required, or `-tags nospell` to do without it.
- **Mentions**: typing `@…` opens a box above the input with the members of the chat (same source as F3); ↑/↓ chooses, Tab/Enter inserts `@nick`, Esc closes (until the word is left). Only the members with an @nick are offered.
- **Sidebar**: header with the title of the mode and the sort order, clickable to change the sort (like F7); the status window is prefixed with `*` in the window list; the `[sort:…]` leaves the status bar.
- **Sidebar**: the counter of unread messages turns red.
- **Scrollbar**: the cursor becomes thick (█) as long as it is held with the mouse.
- **Multiline editing** (`/set multiline on`): Shift+Enter opens an extended input area (one screen line per line of the draft, capped at half the screen), Enter sends and folds it, Esc folds it keeping the draft. Editing a message containing line breaks reopens the area. ↑/↓ move the cursor from line to line, Home/End and Ctrl+A/E act on the current line.
- **Word navigation**: Ctrl+←/→ jumps from word to word (everywhere, kitty protocol or classic CSI sequences).
- **Paste in the extended area**: a multiline paste offers the insertion as it is (`e`) or as a code block (`c`, fenced with ` ``` `) instead of sending it; on sending, the ` ``` ` blocks of the draft go out as a `pre` entity (optional language on the opening fence), and on editing too.
